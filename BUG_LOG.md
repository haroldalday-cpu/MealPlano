# MealPLANO Bug Log

| Date | Bug | Cause | Fix | Test added |
|---|---|---|---|---|
| 2026-11-07 | FR-4 acceptance test said "menudo" was still in the tree after deleting it, and "sinigang" had disappeared. The tree itself was correct. | A two-children delete copies the in-order successor's data into the deleted node. The test held a reference to that node and read `target.key` *after* the delete, so it read the successor's key ("sinigang") instead of the food it had deleted. | Save the key before calling `delete()`. Rule for later code (undo stack, food service): never keep a `FoodNode` reference across a delete; store the name and price instead. | `test_acceptance_fr4_all_three_cases` now also asserts `search(key)` is `None` after each delete. |
| 2026-11-07 | The same FR-4 acceptance test raised `StopIteration` on the AVL tree. | After one delete, the 8-food AVL tree had no node with exactly one child; balancing had produced a valid shape the test had not planned for. | Use a 12-food menu and do the one-child delete first, so every case is present when it is needed. The test asserts all three cases were exercised. | `test_acceptance_fr4_all_three_cases`. |
| 2026-11-07 | Posting a form with a non-ASCII CSRF token (e.g. "ñ") would crash the request with a server error instead of rejecting it. Found by code review during hardening. | `secrets.compare_digest` raises `TypeError` when given `str` values containing non-ASCII characters. | Encode both tokens to bytes before comparing. | `test_non_ascii_csrf_token_rejected_not_crash` |
| 2026-11-07 | Adding a food with a 5,000-digit price crashed the request (500 error). Found by the new hardening test. | Python's `int()` refuses strings over 4,300 digits (a denial-of-service guard) and raises `ValueError`, which the route did not expect. | `parse_pesos` rejects a whole-peso part longer than 6 digits before calling `int()`. | `test_huge_price_and_long_inputs_do_not_crash`, plus `"9" * 5000` in `test_invalid_amounts` |
| 2026-11-07 | `test_password_stored_only_as_salted_hash` failed on Windows: `PermissionError` deleting the temporary database. | The test opened SQLite with `with sqlite3.connect(...) as conn`. That `with` only commits or rolls back; it does **not** close the connection, and Windows will not delete an open file. | Use the project's `db.connect()`, which closes the connection in `finally`. All app code already used it. | Same test. The full suite now also runs clean with `PYTHONWARNINGS=error::ResourceWarning`. |
